dnsd is a DNS server. It answers for one or more zones, such as "home", asks other DNS servers about names in other zones, and lets DHCP servers (dhcpd) and cellular cores (cellcore) set the names of their clients in its zones. It runs in the background, as a service (see "help service"), and starts with the computer. Only one runs on a computer.

Its settings are in /etc/dnsd.conf, which it writes the first time it starts. Each line is a setting's name, then its values, separated by spaces, and # starts a comment. Changes take effect when it starts again ("dnsd restart"):
- "zone home" answers for names ending in .home, from the [home] part of /etc/dnsd.zones. "zone shop.home /zones/shop.zone" takes its names from a file of its own instead. A name is answered by the most specific zone it's in.
- "forward corp 10.1.0.53 10.1.0.54" asks those servers, in turn, about names in the zone corp.
- "upstream 10.0.0.2 10.0.0.3" asks those servers about names in no zone here. Without it, they aren't found: dnsd doesn't use net.dns. It never asks this computer itself.
- "allow-update 10.0.0.2 10.0.1.0/24" lets those computers set and delete names in the zones. This computer always may.
- "key s3cret" makes every update be signed with that secret (dhcpd's update-key, cellcore's hostname key), without spaces or #. Anyone on a link without a passphrase could pretend to be an allowed computer, but can't sign.
dnsd may have no zones of its own, and only ask other servers.

/etc/dnsd.zones has a [zone] line before each zone's names, then a name and an address on each line ("bank 10.0.0.5" is bank.home; "@" is the zone itself). A zone's own file has just the names. They're read again whenever they change, so edits apply at once.

A name may be an alias for another name instead of an address. "www bank" makes www.home an alias for bank.home, in the same zone ("www @" for the zone itself), and "mail mail.corp" for a name written in full, with or without a dot at the end. dnsd follows an alias wherever it leads: to a name in its zones, one set by an update (such as a DHCP client's or a phone's), or one it asks other servers about. Clients see the address at the end. An alias which leads round in a circle, or through more than eight aliases, isn't found, and dnsd says so as it reads the files.

Names set by updates are kept in /etc/dnsd.leases until they expire, or are deleted. A name in a zone's file can't be set, and one set for a computer (or a phone) can't be taken by another until it expires. Answers from other servers are kept for as long as they say, and that a name doesn't exist for a few seconds. If no server answers, the question is refused, so whoever asked tries their next server. A question is forwarded at most three times along a chain of servers, so servers which forward to each other don't pass it round for ever.

Clients find the server through DHCP (dhcpd.conf's dns and domain), the settings net.dns and net.domain, or their cellular network.

Before, dnsd took its zones as arguments, and the setting dnsd.forward. The first time it starts, it moves them to /etc/dnsd.conf, and the setting goes.

ex:
"dnsd start" starts it, from now on.
"dnsd restart" starts it again, with its settings as they are now.
"dnsd stop" stops it, and it doesn't start with the computer.
"dnsd status" says how it's doing, and what it's printed.
"dnsd run" answers in the foreground instead, until Ctrl+T is pressed.
